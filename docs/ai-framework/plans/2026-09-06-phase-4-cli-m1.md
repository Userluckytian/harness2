## Task 1：文件快照存储（D6）

**Files:** `session/snapshots.ts`、`test/snapshots.test.ts`

**行为:** `SnapshotStore(dir)`；`capture({seq, file, before})`（工具执行前）、`commitAfter({seq, after})`（成功后补记；失败/取消不记 after）；条目 append 到 `rewind_points.jsonl`（一行 JSON，崩溃残行按 writer 同款策略容错）。`restore(toSeq, {dryRun})`：对 `seq > toSeq` 的条目**按文件取最早一条**（grok 语义）恢复 before（创建的文件→删除）；冲突检测：当前内容 ≠ after → 标记 `externallyModified`（dryRun 列出；实际恢复时报告后仍执行）。redo 恢复：`restoreAfter(fromSeq)` 取 `seq > fromSeq` 最新一条的 after。路径规范化：条目存绝对路径。

**Steps:** 1. 实现+测试（capture/restore/创建后删除/冲突检测/dryRun/redo after/崩溃残行 ≥10 例，全部临时目录）。2. Commit：`✨feat(core): 文件级快照存储（before/after/冲突检测/dry-run）`

## Task 4：undo/redo 内核语义

**Files:** `session/undo.ts`、`test/undo.test.ts`

**行为:**
- `undoLastTurn(writer, {snapshots?, dryRun})`：定位最近一条 user/message 的 seq U → 目标 seq = U-1（即撤掉该用户消息及其后所有内容，含 attempt 与 tool 事件）；越界（无 user 可撤）→ 明确错误；执行：append `rewind/marker {rewindToSeq: 目标, reason:'undo'}` + `snapshots.restore(目标, {dryRun})`；dryRun 只返回预览（将撤的消息数/文件清单/冲突）不落盘。
- `redoLastUndo(writer, {snapshots?, dryRun})`：从日志推导——找最后一个 rewind/marker M（其 reason 前缀 `undo`），redo 目标 = M.markerSeq - 1（即 undo 前的活动 tip）；校验目标 > M.rewindToSeq；执行 append `rewind/marker {rewindToSeq: 目标, reason:'redo'}` + `snapshots.restoreAfter(M.rewindToSeq)`。连续 undo/redo 链按 marker 链自然成立（n 级）。
- 与 Ph2 的 rewindToSeq 校验（writer 侧 1..lastSeq）兼容：目标恒在界内。

**Steps:** 1. 实现+测试（单级/多级/undo 后新消息再 undo/redo 链往返/dryRun 无副作用/边界：无 user、undo 到 0、redo 无 undo）。2. Commit：`✨feat(core): undo/redo 内核语义（投影截断+快照恢复+n级链）`

## Task 5：chat REPL

**Files:** `packages/cli/src/{chat,render,commands}.ts`、`index.ts` 挂接、`packages/cli/test/chat.test.ts`

**行为:**
- `harness2 chat [--session <id>] [--provider mock] [--root <dir>]`：无 --session 则 resume 最新会话或新建（提示当前会话 id）。readline REPL，提示符 `> `。
- 流式渲染：text-delta 直写 stdout（不换行拼流）；assistant 完成→换行；tool 调用单行 `> tool name(args摘要)` + `< ok/FAILED [callId]`；reasoning 默认不渲染。
- 命令：`/new`、`/sessions [关键字]`（Task 3 list/search）、`/resume <id>`、`/undo [n] [--dry-run]`、`/redo`、`/exit`（或 Ctrl+C 两次/空行 Ctrl+D）。Ctrl+C 在 turn 进行中=取消当前 turn（AbortController），空闲=提示再按一次退出。
- 审批交互：config.approval 决定 ask 时，REPL 内联提示 `允许执行 <tool>? [y]本次 [a]本会话总是 [n]拒绝`；"总是"写入进程内会话级缓存（不落盘）。
- `--provider mock`：用 MockProvider 内置演示脚本（两轮工具调用：write 文件+read），供开发/测试/无 key 演示；不接配置。
- 测试（piped stdin 非交互）：`spawnSync` 或长驻 spawn 喂入命令流，断言输出含流式文本/工具行/undo 预览/审批提示路径；mock provider 全程。

**Steps:** 1. 实现+集成测试。2. Commit：`✨feat(cli): chat REPL（流式渲染/命令集/审批交互/mock 演示）`
