### 0.2 通用规则

- 边界：`packages/core`、`packages/gateway`、`packages/desktop` **零改动**（core/gateway 契约冻结）；`packages/core/test/fixtures/api-surface-baseline.json` 零变化。例外必须先停机上报，不得静默扩权。
- 只改 `packages/cli`（P0 例外：只写 `docs/**` 与独立 spike 目录）。
- 依赖：新增依赖需申报（包名/版本/许可证/体积/为什么自研不可行）；原生依赖必须多平台验证。
- 测试：先红后绿；关键断言可变异验证（删实现必红）；终端交互用**原始字节序列**驱动，不 mock 解析层；`packages/cli` 用例总数只增不减。
- 性能预算：输入响应 < 30ms；10k 行转录 ≥ 30fps（帧耗 < 33ms）；按键不全屏重绘；滚动 5 分钟内存增长 < 20%。
- 可回退：风险项必须带开关（环境变量），默认安全；开关与行为写入文档。
- Git：`<gitmoji><type>(cli): 中文`；小步提交；**push 需编排者/需求方授权**；不提交密钥。
- 证据纪律：**禁止「应该能过」**；没有原始输出 = 没有证据；截图/录屏注明路径与终端环境（Windows Terminal 版本等）。

## 2. P0：渲染层选型 Spike（先决阶段）

**目标：** 用实测数据在 A/B/C/D 四个渲染方案中定案（详见总览 §4），未定案不得开始 P2。

**前置：** 无（可在 P-1 验收前并行开工）。**分支：** `feat/tui-p0-renderer-spike`（或独立 `spike/` 目录；**不得并入主线**）。

**交付物：**

1. `docs/research/<日期>-tui-renderer-spike.md`：结论 + 决策矩阵打分 + **原始数据**（命令、版本、性能数字、失败点、未过项）。
2. 可复跑 demo（独立目录）：每个候选的最小验证程序 + `README`（复跑命令）。
3. 选型建议：推荐方案 + 备选 + 对 P1~P4 的影响说明。

**任务清单：**

- [ ] T0-1 环境登记：Node/pnpm/Windows Terminal 版本、显示器与字体（CJK 宽度）、机器规格。
- [ ] T0-2 Ink 基线（方案 A）：用现有 TUI 测「鼠标+选择+10k 行滚动」的能做到/做不到边界，留数据。
- [ ] T0-3 自研最小渲染层 demo（方案 B）：cell buffer + 差量刷新 + 滚轮；测 10k 行性能与宽字符。
- [ ] T0-4 OpenTUI demo（方案 C）：`@opentui/core` + `@opentui/react` hello-world，测鼠标/滚动/选择/IME/性能/安装体积。
- [ ] T0-5 Rust ratatui demo（方案 D，可选）：最小窗口经 core serve 拿数据；记录额外工具链成本。
- [ ] T0-6 打包验证：npm 安装 + 与 `packages/desktop` 单文件 bundle 的兼容性结论（含替代方案）。
- [ ] T0-7 报告与评审：结论、门槛逐条判定、建议。

**测试要求：** demo 必须可复跑；性能用**同一份 10k 行合成数据**；记录冷启动时间、常驻内存、安装体积。

**代码审查：** spike 代码不入主线 → 改为**报告评审**（编排者 + 需求方参加）。

**验收（编排者复跑）：**

1. 复跑 demo 命令，核对报告数字与原始输出一致；
2. 逐条核对总览 §4.2 通过门槛（平台/性能/打包/体验/许可），**缺一不可**；
3. 结论明确：推荐 + 未过项 + 回退方案。

**出口条件：** 报告通过评审 + 选型定案记录在案。**未过门槛的方案不得进入 P2**；若全部不达标 → 回退 A 档并重新评估目标（如实登记，不硬上）。

**工期：** 2~4 人日 · **风险：** 原生依赖/打包兼容；C 不达标则选 B/D。

## 3. P1：输入与事件层

**目标：** 建立**渲染引擎无关**的统一输入模型，并产出键位对照表。

**前置：** P-1 合并 `main`（避免与进行中分支冲突）。**分支：** `feat/tui-p1-input`。

**交付物：**

1. `packages/cli/src/input/**`：事件解析（kitty CSI-u、SS3 功能键、SGR 鼠标、bracketed paste、DECSET 1004 焦点）与分发（按浮层/卡片/输入框/滚动区优先级）。
2. `docs/`《终端键位对照表》：grok 键位 vs 我方现状 vs 目标 vs **差异理由**（已知冲突：`Ctrl+O`、`Ctrl+G`、`Ctrl+J/K`）。
3. 开关约定（`HARNESS2_MOUSE`、`HARNESS2_NOTIFY` 等）统一说明。

**任务清单：**

- [ ] T1-1 事件类型定义（含来源上下文与消费语义）
- [ ] T1-2 原始字节解析器（增量、分片、超时回注）
- [ ] T1-3 分发器与焦点/优先级规则（与浮层/卡片互斥契约）
- [ ] T1-4 迁移现有键盘/鼠标/焦点路径（行为不回归）
- [ ] T1-5 键位对照表 + 冲突项决策（需编排者确认）
- [ ] T1-6 测试与真机（IME/粘贴/中文）

**测试要求：** 解析用例喂**原始字节**（含分片/半包/超时）；先红后绿；关键断言做变异验证；键盘回归 `test/tui/keyboard.test.tsx`；`test/input/` 新增用例。

**代码审查：** 独立审查（重点：解析健壮性、消费/回注不吞键、与 Ink 通道共存、开关默认值）。

**验收（编排者复跑）：**

1. `pnpm --filter harness2 exec vitest run test/input test/tui` exit 0；
2. 键位对照表逐条有事实依据（含冲突决策），抽查 2~3 条在真机上按键验证；
3. 边界检查：diff 仅 `packages/cli/**`（+docs）。

**出口条件：** 解析覆盖矩阵全绿 + 键盘零回归 + 键位表评审通过。**工期：** 3~5 人日。

## 4. P2：渲染与布局层（依赖 P0 定案）

**目标：** 实现新渲染核心并对齐 grok 布局（分层、输入框贴底、scrollback pane、弹层锚点、resize、宽字符）。

**前置：** P0 定案 + P1 完成。**分支：** `feat/tui-p2-renderer`。

**交付物：**

1. 渲染核心：布局引擎（纵向分层/弹性）、差量刷新、宽字符测量、resize、alternate screen 生命周期。
2. 组件迁移：`TranscriptView`（scrollback pane：跟随/锚定/粘性 + 滚动条）、`Composer`（贴底 + 底边指示）、`StatusBar` 迁底、`OverlayHost`/`Modal`（锚定输入框上方）、`panels`。
3. `scripts/bench-tui.mjs`（10k 行合成转录性能基线）+ 视觉快照测试。

**任务清单：**

- [ ] T2-1 布局引擎与基础组件原语
- [ ] T2-2 差量刷新与 alternate screen 生命周期（异常退出恢复鼠标上报/光标）
- [ ] T2-3 scrollback pane（跟随/锚定/粘性/滚动条/鼠标滚轮）
- [ ] T2-4 Composer 贴底 + 高度上报 + 底边指示
- [ ] T2-5 浮层/面板锚定与高度让位
- [ ] T2-6 宽字符/CJK/resize 处理
- [ ] T2-7 快照测试 + 性能基线脚本

**测试要求：** 字符网格快照（固定 rows/cols）；resize 用例；性能门槛（见 §0.2）；真机录屏。

**代码审查：** 独立审查（渲染正确性、资源释放、性能、回退开关有效性）。

**验收（编排者复跑）：**

1. `pnpm --filter harness2 exec vitest run test/tui` exit 0；
2. `node scripts/bench-tui.mjs` 原始数字达标（帧耗/输入延迟）；
3. 真机：布局截图对比（对照 grok 截图）、resize、alt-screen 进出恢复；
4. 边界与冻结区检查。

**出口条件：** 快照稳定 + 性能达标 + 真机确认（需求方签字）。**工期：** 10~20 人日（取决于 P0 选型）。
