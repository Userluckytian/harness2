## 0. 施工总则（与终端计划同规，简版）

1. **流程八步**：拉分支 → 实施（小步提交）→ 自测（先红后绿 + 全量回归）→ 交证据（命令原文+原始输出+exit code）→ 独立代码审查（P0/P1/P2）→ 修 P0/P1 → 编排者独立复跑验收 → 合并 main + 更新文档。**每任务出口条件满足才进下一任务**。
2. **边界（红线）**：只改 `packages/desktop/**`（文档另计）；`packages/core`、`packages/gateway`、`packages/cli` **零改动**（core/gateway 契约冻结）。需要 core 能力时**停机上报**，走解冻流程，不得复制 core 逻辑。
3. **Git**：`<gitmoji><type>(desktop): 中文`；小步提交；**只推自己的分支**；不 push main；不提交密钥。
4. **测试纪律**：先红后绿；关键断言做变异验证（删实现必红）；桌面端测试总数只增不减（当前基线 304 passed + 1 skipped）；`pnpm --filter @harness2/desktop test` 与 `pnpm lint` 必须绿（**上次 TUI 阶段就栽在漏跑 lint**，本次交付前必跑 `pnpm lint` 与 `pnpm -r typecheck`）。
5. **界面**：本补丁不碰视觉/主题/动画；功能可用即可，不做像素级调整。
6. **证据**：真机项给截图/录屏路径 + 终端/系统环境；禁止「应该能过」。

## 1. 与「真机验收（类 1）」并行的影响控制（重要）

用户在同一时间会做桌面端真机验收，两者**必须互不干扰**：

| 层     | 规则                                                                                                                                                                                            |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 代码   | 实施同事用**独立 git worktree + 独立分支**；不得切换/占用用户的测试工作区（当前：用户目录 `D:\AI_Projects\harness2`，main 相关文档区 `D:\AI_Projects\harness2-main`）                           |
| 产物   | 同事只在**自己 worktree** 里 build；用户测试使用已构建产物/安装包，不受同事重建影响                                                                                                             |
| 运行时 | ⚠️ 桌面端会读 `serve.lock`「采纳已有 serve」且共用 `~/.harness2`。**同机同用户同时跑两个桌面实例可能串数据**：错开时间；或同事启动时设 `USERPROFILE=<临时目录>` 隔离 home；或同事单用 `--smoke` |
| 仓库   | 同事只推自己的分支；`main` 由编排者验收后合并 → 用户测试期间 main 稳定；用户的测试结论对应冻结 SHA                                                                                              |
| CI     | 同事 push 触发远程 CI，不占用用户本机                                                                                                                                                           |

## 2. 任务清单（按顺序；同文件串行）

> 标注「可选」的任务，由编排者/用户决定是否纳入本次补丁；不纳入时在交付说明登记为「未做」。

### PD1 — redo 冲突守卫接 UI（P0 内先做）

- **现状**：undo 侧已有外部改动冲突守卫并接 UI；**redo 的冲突守卫未接入 UI**（`redo` 仍走既有 `api.redo`）。
- **目标**：redo 前同样做冲突检测；冲突时阻止并给出可行动提示（不静默重放）。
- **测试**：新用例：先制造外部改动 → redo → 断言被阻止 + 提示；再回归既有 undo 守卫。
- **验收**：`pnpm --filter @harness2/desktop test` exit 0；新用例先红后绿 + 变异验证。
- **出口**：守卫生效且提示清晰；不改变 undo 语义。

### PD2 — F7 故障注入用例（中途断 WS/EOF）

- **现状**：重订阅/快照/ack 丢失已验；**中途断 WS / EOF 的故障注入未做**。
- **目标**：断开连接中途（流式中/审批等待中）→ 不永久 loading、不假报停止、重连后恢复订阅并拉快照。
- **测试**：用真实 serve + 可断开测试夹具（或用代理层强制断链）构造：断点位置覆盖 流式文本中 / 工具执行中 / 审批等待中；断言三态与恢复。
- **验收**：新用例（先红后绿 + 变异验证）；真实 serve 参与（不得 mock 掉连接层）。
- **出口**：三类断点场景全覆盖。

### PD3 — F6 桌面侧并行/写互斥观察用例

- **现状**：K=2 并行与写互斥由 core `TaskCoordinator` 保证；**桌面侧未另测**。
- **目标**：桌面任务面板能如实显示并发/排队/停止状态；写互斥在桌面观察面可见。
- **测试**：真实 serve + 派两个只读任务 + 一个写任务，断言面板状态与停止行为。
- **验收**：新用例 + 证据；不得复制 core 调度逻辑。
- **出口**：面板状态与 core 行为一致（观察而非复刻）。

### PD4 — F4 断线重复点击幂等

- **现状**：`ask→拒绝→文件不存在` 已验；**断线场景下重复点击审批按钮未专项**。
- **目标**：断线/重连期间重复点击审批：不重复提交、不产生重复决定、UI 有禁用/排队反馈。
- **测试**：模拟断线 + 连点；断言后端只收到一次决定、UI 状态正确。
- **验收**：新用例（先红后绿 + 变异验证）。
- **出口**：幂等成立且有反馈。

### PD5 — F8 配置写路径（改模型/审批模式并如实标注生效范围）

- **现状**：配置面板只读展示真值；**「改配置并重启生效」写路径未做**。
- **目标**：支持从桌面改**全局** config.json 的模型/审批模式（白名单），写前校验、密钥拒绝、写入原子；提示「新会话/重启后生效」并如实标注范围。
- **测试**：写路径单测（含非法值/密钥拒绝/JSONC 损坏拒绝/原子写）；重启后生效的联调用例。
- **验收**：新用例 + 手工/联调证据；**不得打印明文密钥**。
- **出口**：写入生效可追溯；失败有可行动提示。

### PD6 — `updateSettingsConfig` root 口径一致化

- **现状**：主进程 `config-file.ts` 内部以 `process.cwd()` 作项目根读合并视图，与 `settings:getConfig` 的 `deps.root` 口径不一致（写路径本身正确）。
- **目标**：统一 root 口径（以 `deps.root` 为准），补用例锁住。
- **测试**：同一 root 下读/写视图一致；跨 root 不串。
- **验收**：新用例 + 回归。
- **出口**：口径统一，无行为回归。

### PD7 — 文件树只读列目录 IPC（可选，安全敏感）

- **现状**：无只读目录列举 IPC（当时登记为遗留，因涉及路径边界安全设计）。
- **目标**：只读列目录（工作区内），走 preload 白名单；realpath 边界校验；不暴露通用 fs。
- **测试**：路径越界（`..`、符号链接、junction）必被拒；正常列举正确。
- **审查**：**必须安全专项审查**（P0 级门禁）。
- **出口**：安全审查通过 + 越界用例全绿。评估超范围时可在交付说明中「未做」并说明。

### PD8 — 关窗口对话框自动化测试（可选）

- **现状**：关窗口对话框与「保持后台运行=最小化」未做自动化 UI 测试（主进程窗口事件）。
- **目标**：用 Electron 自动化（如 Playwright Electron）覆盖决策语义；无法落地则保留真机项并登记原因。
- **出口**：能自动化的部分有测试；不能的部分有如实登记。

### 不在本补丁范围（明确排除）

- **审批模式「项目配置覆盖」根治**：需 core 会话级配置面 → 走解冻窗口，另行立项。
- **cron 完成事件 UI 面**、**主题/动画/美化**、**文件树之外的 IDE 能力**：增强项，等用户真机确认后另议。
