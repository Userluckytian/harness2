## 0. 为什么要开这个总纲（问题诊断）

用户（领导）的真实诉求是一句话：**「终端打开后要长得像 grok，内核用我们自己的」**。

对照现状，我们发现的不是「没做」，而是**做错了地方**：

| 事实                                                                                           | 证据                           |
| ---------------------------------------------------------------------------------------------- | ------------------------------ |
| 我们已有一份 95 条的 grok 复刻规格，复刻等级默认「必刻」，44 条已完成                          | `docs/refs/refs-grok-build.md` |
| 但 95 条里**只有 8 条**是「长什么样」（G-01～G-06 布局渲染、G-84 `/theme`、G-92 终端原生主题） | 同上，分组索引表               |
| 而 G-1x 这 6 条恰好是完成度最差的一组（5 🟡 · 1 ✅）                                           | 同上                           |
| 其余 87 条全是「手感」：键位、Esc 语义、斜杠命令、状态机                                       | 同上                           |

**结论：团队在复刻「交互行为」，领导在看「视觉外观」。两边都在卖力，就是对不上。**

本总纲的唯一目的：**把人力从「手感」切到「长相」，并且把「像不像」变成一个可签字的数字。**

## 1. 目标与非目标

### 1.1 目标

1. **建立视觉规格**：新开 `V-*` 编号体系（与现有 `G-*` 行为规格并列），逐条定义 grok 的布局、配色、边框、图标、动效、欢迎屏。
2. **建立量化验收**：用 `scripts/tui-parity/` 抓屏台产出的 `.txt` 屏幕网格做逐格 diff，输出**吻合度百分比**，取代「像 / 不像」的审美争论。
3. **落地视觉复刻**：主题系统、布局骨架、卡片样式、状态图标、spinner 动效对齐 grok。
4. **补齐领导点名的体感需求**：声音提醒（最优先，半天可见）、宠物挂件；codemap 单独立项。
5. **补上管理欠账**：`docs/diary/` 断更 7 天（最后一篇 `2026-09-09.md`，而提交一路到 09-16），这是领导 init 需求第 6 条明确要过的东西。

### 1.2 非目标（本总纲明确不做）

- ❌ **不 fork grok-build**。理由：166 万行 Rust / 85 crate（我方 5.96 万行 TS 的 28 倍）、上游明确不接受外部贡献（无回流路径）、纯 TUI 单形态（桌面端一行都没有）、技术栈整体迁移成本高于把 harness2 做完两遍。
- ❌ **不追 G-8x 剩余 25 条 🟡 斜杠命令**。本总纲期间冻结，待视觉收口后另行排期。
- ❌ **不追像素级 1:1**。字体度量、抗锯齿、字距、终端渲染差异**物理上不可复刻**，抓屏台 README 自己已如实声明。我们追的是**字符级 + 配色级**吻合。
- ❌ **不动 `packages/core` 与 `packages/gateway`**（2026-09-11 契约冻结）。确需改动走编排者解冻窗口。

## 2. 铁律（冲突时以本节为准）

1. **冻结区不得触碰**：`packages/core/**`、`packages/gateway/**`。越界信号＝`packages/core/test/fixtures/api-surface-baseline.json` 发生变化。本总纲全程该文件应为 **0 行 diff**。
2. **红线 3 不得破**：core 不依赖 UI；UI 不得绕过 core 直接操作会话文件。视觉工作**只在 `packages/cli` / `packages/desktop` / `packages/ui-shared` 内**。
3. **禁止凭想象设计**（AGENTS.md 第 7 条）：`docs/refs/refs-grok-visual.md` 里没有的视觉条目，**先补条目再写代码**。每条 `V-*` 必须附 grok 抓屏证据帧路径。
4. **证据优先**（AGENTS.md 第 2 条）：验收命令必须实际跑过并贴输出，禁止「应该能过」。
5. **不伪造**：抓不到的帧写「未抓取」，对不齐的格子写「未对齐」。**严禁用 AI 生成图或占位图冒充真机截图。**
6. **密钥不进 git**；`git push` 与发布动作需人类明确授权。
7. **每日必写** `docs/issue-log/YYYY-MM-DD.md` 与 `docs/diary/YYYY-MM-DD.md`；开工先读 `docs/issue-log/OPEN.md`。

```

   ↓

   · 生产缺陷      → 必须本阶段修完，不得下放
   · 测试侧抖动    → 屏障化加固（禁止放宽断言），并做变异验证证明断言非空转

## 6. 关键技术决策（已定，执行者不要再讨论）

### 6.1 grok 的配色从哪来？—— 从抓屏提取，不从源码考古

已核实：`crates/codegen/xai-grok-pager/src/slash/commands/theme.rs`（26KB）里 **hex 色值 0 个、`Rgb(` 0 个**——颜色不硬编码在那里。

能确定的只有主题名单：

```
groknight（默认暗色）· grokday · tokyonight · terminal（跟随终端原生）· transparent · auto / system
```

**决策：不去 Rust 源码里找调色板。** 抓屏台用的 `pyte` 终端仿真，解析 ANSI 后**每个 cell 都带前景/背景色属性**，直接从 grok 抓屏逐格导出真实配色即可。这是 V1-A 的核心任务。

### 6.2 「像不像」如何量化

抓屏台每次产出 `.png` + **`.txt`（屏幕网格，逐格保真）**。README 已声明「结论以 `.txt` 为准，PNG 只用于人眼比对」。

**吻合度定义**（V1-A 实现，V5-G 定稿）：

```
字符吻合度 = 同位置字符相同的 cell 数 / 总 cell 数
配色吻合度 = 同位置 fg+bg 均相同的 cell 数 / 总 cell 数
场景吻合度 = 字符吻合度 × 0.6 + 配色吻合度 × 0.4
```

**验收阈值**（可由领导调整，先按此执行）：

| 阶段    | 字符吻合度目标 | 配色吻合度目标 |
| ------- | -------------- | -------------- |
| V2 收尾 | ≥ 80%          | ≥ 70%          |
| V3 收尾 | ≥ 90%          | ≥ 85%          |
| V5 收尾 | ≥ 93%          | ≥ 90%          |

> 达不到 100% 是**正常且预期**的：欢迎屏含版本号/路径/时间等本就不同的内容，工具卡片含我方自有工具名。记分卡须把这类「合理差异」单独列为**豁免格**并说明理由，不计入分母。

### 6.3 抓屏基线现状（已核实，别重复劳动）

`scripts/tui-parity/out/` 下 grok 侧基准帧**已抓 13 个场景**：

```

B1-stream       ours=3 grok=3     J1-busy-queue   ours=2 grok=2
C1-slash        ours=2 grok=2     K1-canvas110x30 ours=2 grok=2
C2-help         ours=2 grok=2     K2-canvas160x40 ours=2 grok=2
D1-tool-cards   ours=1 grok=2     L1-tool-failure ours=1 grok=1

B2-long-code    ours=1 grok=0  ← 缺

## 9. 风险与降级

| 风险                                                    | 概率   | 缓解                                                                                                   |
| ------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------ |
| grok 抓屏额度受限，基准帧不够用                         | 中     | V0 一次性把缺帧补齐；后续尽量复用 `out/` 已有帧，不重复跑 grok 侧                                      |
| `pyte` 拿到的颜色是 ANSI 索引而非真彩，导致配色表不精确 | 中     | V1-A1 同时记录索引色与真彩色；若终端只报索引色，如实声明精度边界，配色吻合度按索引比对                 |
| `next-shell.ts` 236KB 巨型文件成为并行瓶颈              | **高** | 同阶段只允许一轨改它；可考虑在 V2 前先做一次纯机械拆分（**但需单独开 refactor 窗口，不混进视觉阶段**） |
| 吻合度阈值达不到，团队士气受挫                          | 中     | 阈值是**指导值不是军令状**；记分卡展示**趋势**（每阶段涨了多少）比展示绝对值更重要                     |
| 领导中途追加新需求                                      | **高** | 一律先进 `docs/issue-log/OPEN.md` 待排期，**不插队进行中的阶段**；由编排者在阶段边界统一评估           |
| 测试抖动被误判为缺陷                                    | 中     | 沿用既有做法：隔离复跑 3 次 + 变异验证；抖动项屏障化加固，**禁止放宽断言**                             |
