# ZCode GUI 改造总纲（Z0–Z7）

> 立项日期：2026-10-10 · 立项人：编排者（主会话）· 依据：用户 2026-10-10 决策
> 关联文档：`refs-zcode.md`（视觉与组件规格）· `refs-zcode-layout.md`（布局与 IA）· `zcode-ui-traceability.md`（功能台账）
> 本总纲**不取代**既有计划：V 程序（CLI 复刻 grok）与 R 程序（桌面改造）并行运行，见 §7。

---

## 1 目标

把 harness2 的 **GUI（桌面 + Web）壳**按 ZCode **完全还原**——布局、区域、默认展开折叠、页面摆放、视觉与组件规格逐条对齐；**我们自己的附加能力**按功能台账（A/B/C 组）另行补齐，不混入"复刻"范畴。

**明确边界**：

| 在范围内                                 | 不在范围内                                                                                          |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------- |
| GUI 壳骨架（窗口/左栏/内容区/右栏/浮层） | **CLI 端**（保持 grok 复刻，V 程序管）                                                              |
| 默认展开折叠矩阵与四种场景形态           | ZCode 的业务页面（插件商店商业形态、bots 面板、SSH 向导、whiteboard、treemapping、developer-tools） |
| 视觉/组件/主题/设置页/对话页规格         | office 模式（`InterfaceMode`，仅留条目）                                                            |
| 分屏工作台、轨迹页、代码查看器、命令中心 | ZCode 的 Cordis 插件运行时兼容                                                                      |

**"完全还原"的操作定义**：以 `refs-zcode-layout.md`（`Z-01`～`Z-45`）与 `refs-zcode.md`（`Z-60`～`Z-95`）为**唯一依据**；凡文档里标 `必刻` 的条目，须逐条对齐并在验收表登记证据；标 `参考` 的可形似；标 `不采纳` 的不做。

## 4 每阶段的执行闭环

```
① 重跑针对性调研（拉上游 → 重读 refs 条目 → 核对台账）
② 更新台账对应行（调研产出 / 状态）
③ 起草本阶段详细计划（含：元信息·Global Constraints·File Structure·契约·
   Task 1..N·代码审查·验收标准总表·风险与降级·交接提示词·残留手工项）
④ 派「实现子代理」执行（交接提示词五段：基线 / 做 / 不做 / 工作方式 / 交卷）
⑤ 派「测试子代理」补测与跑测
⑥ 派「只读审查子代理」出 P0/P1/P2 报告（按 CODE_REVIEW.md，含八条红线）
⑦ 编排者亲自重跑证据命令验收（build / typecheck / 六包 test / 抓屏比对）
⑧ 通过 → 台账回填"已完成"；不通过 → 写入下一阶段计划的「上阶段遗留」
```

**硬约束（既有规则，不放松）**：同一时刻至多 1 个子代理（例外：两个互不写文件的只读审查）；验收不可委托；禁止假全绿；导出面变更须同批同步 `api-surface` 快照；`core`/`gateway` 契约冻结。
