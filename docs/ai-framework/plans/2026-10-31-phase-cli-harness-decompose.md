# 阶段 F1-DECOMP：next-shell 闭包工厂拆解（2026-10-31 立项，**本阶段只立计划不实施**）

> 来源：FIX-1 优化分析轮发现 F1（高严重度/大成本，全仓最大单点维护成本）。用户指令「全部修一轮」中该项按「大块工作先立阶段计划」原则单独立项，实施排期由人类拍板。

## 1. 背景与证据（已独立复核证实）

- `packages/cli/src/tui/next/next-shell.ts:1064-4575`：`createNextChatHarness` 为 **3511 行**单个闭包工厂函数，实测内部含 **126 个闭包函数、56 个函数顶层 `let` 状态变量**，掌控渲染基座切换/按键路由/审批卡/选择复制/子代理动画等几乎全部 TUI 行为。
- 同模式第二例：`packages/zcode-adapter/src/real/agent-service.ts:141-1657`（约 1516 行 `createAgentService`）。
- 危害：任何状态机/按键语义改动需在 3500 行作用域内定位变量与闭包的隐式耦合，改坏一处即全局回归。

## 2. 目标与非目标

- **目标**：把两座闭包工厂拆为职责清晰的模块/类边界，行为零变化；`createNextChatHarness` 最终缩为「状态域装配」薄壳（目标 <300 行，硬指标在 T1 摸底后定）。
- **非目标**：不改任何交互、视觉、按键语义、性能特征（用户可见行为冻结）；不顺手改功能；不引入新运行时依赖。

## 3. 前置闸门 G0（强制，实施前第一件事）

按 `AGENTS.md` 第 7 条与 `docs/refs/README.md` §2 六步流程执行：拉取 `D:/AI_Projects/refs/{grok-build,deepseek-harness,hermes-agent,ZCode}` 最新 → 判定 refs 文档是否过期 → 补条目 → 再开工。**本轮为纯结构重构、不改交互，refs 流程的产出物是「行为零变化清单」：把涉及文件的交互行为逐条登记为回归基线。**

## 5. 风险与对策

- **最大风险=行为回归**：3500 行隐式耦合，编译器只保类型不保语义 → 对策=特征化测试先行 + 抓屏对照 + 每批变异验证。
