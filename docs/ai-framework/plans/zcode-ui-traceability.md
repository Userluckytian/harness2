# ZCode GUI 改造 · 功能台账（traceability）

> 本文件是 **harness2 GUI 改造（Z0–Z7）** 的功能总账，用于防止"计划里的能力点被遗漏或遗忘"。
> 它是一份**活文档**：每个小段开工前必须更新对应行的「调研产出」与「状态」。

---

## 1 使用规则（强制）

1. **开工前先重跑调研**：任何小段动工前，必须
   - 重试拉取上游（`D:/AI_Projects/refs/ZCode` 等），登记 commit；
   - 重读本行「调研产出」列指向的 refs 条目（`refs-zcode.md` / `refs-zcode-layout.md` / `refs-*.md`）；
   - 若该行标了 **「需新调研」**，必须先补一份针对性调研并回填「调研产出」，才允许进入实现。
2. **回填**：小段完成后回填「调研产出」（具体条目号）与「状态」。
3. **不得跳步**：状态为 `待启动` 的行，不得直接进入实现。
4. **不通过项下放**：验收不通过的行，在「阶段/小段」列追加 `→ 遗留至 Z?`，并在下一阶段计划的「上阶段遗留」小节登记。
5. **禁止假全绿**：无证据的项一律标 `未验证`。

### 状态图例

`待启动` · `调研中` · `调研完成` · `实现中` · `待测试` · `待审查` · `待验收` · `已完成` · `未验证` · `已定不做`

### 等级图例

`必刻`（逐键位/文案/尺寸对齐 ZCode）· `参考`（形似即可）· `补齐`（功能要有、交互自定）· `不采纳`（明确不做）
