## 关键结论

1. **撤回恢复 vs 分叉的长期答案**：三家（opencode/grok/dsh）数据层趋同——append-only 日志 + 撤回只是投影变化。推荐：undo/redo 为主（P1，opencode 语义），fork 为辅（P1.5，同一机制免费获得），grok 的三模式 + 冲突检测 + dry-run 作为 undo 增强。底层一套，交互两皮。
2. **记忆系统**：hermes 方案完整且 MIT——文件记忆 + 硬预算 + 写入 gate（off/询问/自动 = 用户要的开关）+ nudge 后台 review；Tokeny 的记忆访问统计作为后期质量闭环。
3. **Tokeny 已确认闭源**（Electron，GitHub, Inc. v1.5.7），不做逆向集成；其"按场景分模型"的 `{channelId, model}` schema 可直接借鉴。
4. **技术栈推荐**：TypeScript/Node monorepo + Electron 桌面 + JSONL/SQLite 存储 + QQ 官方 Bot API 网关（依据：dsh 验证 TS 多形态、本机四家应用三家 Electron、grok 证明 Rust 体量风险）。
5. **轨迹优先可行**：dsh 的"Model-visible ⟺ logged"不变量 + append-only 代际文件是可照抄的地基，且快照回放测试让 CI 无需 API key。
