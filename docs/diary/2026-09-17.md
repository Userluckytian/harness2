## 关键结论

1. **账能补，谎不能补**：7 篇日记里凡是 git/issue-log 撑不住的细节一律写「无记录」（例如 09-13 的 CI run 编号、09-14 的 bench 原始数字、09-16 无 issue-log）。这份日志领导会直接看，写「无记录」比编一个数字安全得多。
2. **估值的价值在于可比对，不在于精确**：记分卡 V0 列的 `~82%` 不是实测，但配上「结构指纹」那组硬数字（非空行/框线/实字），V1-A 的 `diff.py` 出来后就有独立交叉校验点，也能算出「涨了多少」。
3. **两次「按计划做不下去」都不是代码问题**：一次是分支基点选错（`main` 上没有对照台），一次是上游额度变了。都属于「登记 + 请人类裁决」类，硬闯只会产出假证据。
4. **P10/P11 停在本地分支已经是 V1 的阻塞项**，不只是历史污点——V1 要重跑 `run.py`，而那套东西只活在未合入的分支上。
