# docs/refs —— 参考项目分析规范（强制）

本目录是 harness2 **上层壳（`desktop` / `cli` / `web`）**交互、样式、页面布局的**唯一设计依据**。
任何人、任何模型、任何同事，在动手做壳层之前**必须**先完成第 2 节的开工流程。

> 本规范由用户于 2026-09-13 确认，长期有效。根 `AGENTS.md`「强制遵循」第 7 条引用本文。

---

## 1 为什么存在

harness2 的定位是：**harness 必备能力下沉到 `core`，上面三端只是壳。**

目标目录结构（演进方向）：

```text
harness2/
├── core/      # agent loop、记忆、会话、压缩、审批、工具、MCP、技能、cron、子代理 —— harness 必备能力
├── cli/       # 终端壳
├── desktop/   # 桌面壳
└── web/       # 浏览器壳
```

当前实现位于 `packages/{core,cli,desktop,gateway}`，尚无 `web` 包；由阶段计划负责收敛。

**核心约束：壳不许自己发明交互。** 壳的每一处交互、样式、布局，都必须能在本目录文档里指到一个条目编号（`G-*` / `D-*` / `H-*`）。找不到条目就先补条目，再写代码。

## 2 开工流程（MUST）

任何涉及壳层（`cli` / `desktop` / `web`）的工作，开工顺序固定为六步，**不得跳步**：

1. **拉取上游最新代码**（三个仓库都要）：

   ```powershell
   foreach ($p in @('D:\AI_Projects\refs\grok-build','D:\AI_Projects\refs\deepseek-harness','D:\AI_Projects\refs\hermes-agent')) {
     git -C $p fetch --all --prune
     git -C $p pull --ff-only
     git -C $p rev-parse --short HEAD
     git -C $p log -1 --format='%cI'
   }
   ```

   无网络时如实登记「本轮未拉取，沿用 commit X」，不得假称已更新。

2. **对照文档头部「分析基线」判断是否过期**（判定规则见第 4 节）。
3. **过期则重新分析**：按各文档已有小节逐项走查上游源码/文档，**补充新特性、修正失真条目、删除上游已移除的条目**（删除也要留痕，见第 5 节）。
4. **更新文档**：刷新「分析基线」表 + 在「本轮更新记录」追加一行（日期、执行者、上游 commit、改了什么）。
5. **只依据文档实施**：实现阶段的每个改动都要引用条目编号；条目里没有的交互，先回到第 3 步补条目。
6. **提交前跑格式闸门**：`pnpm exec prettier --check .`（根 `lint` 覆盖 `.md`，文档提交挂 CI 是历史上真实发生过的事故）。

## 3 文档结构模板（三份文档统一）

每份 `refs-<项目名>.md` 固定包含以下小节，顺序不变：

| 小节               | 内容要求                                                    |
| ------------------ | ----------------------------------------------------------- |
| 分析基线           | 远程地址、分析 commit、上游提交时间、分支、分析日期、分析者 |
| 定位与仓库结构     | 技术栈、顶层目录、关键包/crate 分工（要能指到路径）         |
| 权威依据           | 本次结论来自哪些文件/目录（相对参考仓库根的路径清单）       |
| 交互 / 布局 / 样式 | 按「区域 → 行为 → 边界条件」展开，含键位表、状态机、语义表  |
| 功能面清单         | 该项目提供的能力全景（`refs-hermes-agent.md` 以此为主体）   |
| 复刻矩阵           | 条目编号表：ID / 条目 / 依据路径 / 复刻等级 / 状态 / 落点   |
| 与 harness2 差距   | 逐条对比当前实现，写清「现在是什么、要变成什么」            |
| 不采纳清单         | 明确不做的上游能力 + 理由（禁止静默丢弃）                   |
| 本轮更新记录       | 追加式变更日志（日期 / 执行者 / 上游 commit / 变更摘要）    |

### 条目编号规则

| 前缀  | 来源             | 用途                      |
| ----- | ---------------- | ------------------------- |
| `G-*` | grok-build       | CLI 交互条目              |
| `D-*` | deepseek-harness | 桌面/Web 壳布局与页面条目 |
| `H-*` | hermes-agent     | 功能完整性条目            |

编号一经分配**永不复用、永不重排**；条目作废时保留编号并标 `➖` + 理由。

### 复刻等级

| 等级       | 含义                                                             |
| ---------- | ---------------------------------------------------------------- |
| **必刻**   | 逐键位、逐文案、逐状态复刻，偏差即 bug（CLI 对 grok-build 默认） |
| **参考**   | 形似即可，允许本地化与技术栈替换（桌面壳对 deepseek 默认）       |
| **补齐**   | 功能要有，交互形态自定（对 hermes 默认）                         |
| **不采纳** | 明确不做，必须写理由                                             |

### 状态符号

`⬜` 未开始 · `🟡` 部分完成 · `✅` 完成并有证据 · `❌` 失败/回退 · `➖` 不适用（须写理由）

## 4 过期判定（硬规则）

满足**任一**条件即视为文档过期，必须重新分析后才能继续实施：

1. 参考仓库当前 `HEAD` 与文档「分析基线」记录的 commit 不一致；
2. 距文档「分析日期」超过 **30 天**；
3. 实施中发现文档与上游实际行为冲突（此时以上游为准，并当场修文档）。

---

## 5 禁止事项

1. **禁止凭记忆或印象写参考文档**。每条结论都要能指到参考仓库里的具体文件或目录路径。
2. **禁止在文档之外引入未登记的交互设计**。要加新交互：先加条目，再写代码。
3. **禁止把壳逻辑写进 `core`**，也禁止在壳里重写 `core` 已有能力（重复实现即返工项）。
4. **禁止静默丢弃上游能力**。不做就标 `➖` 并写理由，供后续模型复核。
5. **禁止只改文档不改状态**，也禁止只改代码不回填条目状态；两者必须同批提交。
6. **禁止摆不可点的假入口**（根 `AGENTS.md` Global Constraints #7）。壳上出现的控件必须真实可用，否则不允许出现。
