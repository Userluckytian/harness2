**core 有、ZCode UI 无消费（投影层可丢弃，不构成阻塞）**：`memory/snapshot`（C:session/types.ts:130-132，UI 走通用兜底行）、`compaction/applied`（→timelineMarker compact，部分消费）、`rewind/marker` 影子事件语义（core 独有的遮蔽投影，ZCode row.removed 只表达「删除之后」——**语义差异点：core rewind 保留影子可导出，v4 row.removed 不可逆，投影时按 core 语义发 snapshot resync 更安全**）、`step/start|end`（无行对应，可并入 turnHeader 聚合）、`nudge-started/finished`（记忆复盘，ZCode 无此概念）、`cron` 帧（Z:automation 走独立服务面）、`assistant/attempt`（映射为 failed assistantText row 或丢弃）。

**关键结论**：v4 水位机制（fromSeq/toSeq/logEpoch/seq，Z:transport.ts:168-191）与 core 的 seq/epoch/lastSeq（C:interaction/types.ts:100-106）**结构同源**，ZS2 最小竖切可直接以 session.v1.jsonl 的 seq 空间驱动 v4 帧；最大词表工作量在「core 扁平事件 → v4 自包含 row 模型」的投影层（rowId 分配 + row.upserted 状态机 + pendingInteractions 联动），建议以投影层单测覆盖每类事件（总纲 §4 对策）。
